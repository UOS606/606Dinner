# 음성인식 기반 디너 주문 자동화 서비스 (606Dinner)

기존의 클릭 중심 주문 흐름을 **음성 한 번의 발화로 자동화**하는 디너 주문 웹 서비스입니다.  
사용자는 메뉴 선택, 수량 변경, 추가·삭제, 주문 확정까지의 과정을  
여러 단계의 클릭 없이 **자연어 음성 명령만으로 처리**할 수 있습니다.

---

## 프로젝트 개요

### 문제 인식
- 기존 주문 웹 서비스는 다단계 클릭과 입력에 의존
- 메뉴 선택 → 수량 입력 → 수정 → 확인 과정이 반복적으로 발생
- 주문 과정에서 사용자의 조작 부담이 큼

### 해결 방식
- 음성 인식을 통해 사용자의 자유 발화를 입력으로 수집
- 자연어 주문을 구조화된 주문 데이터(JSON)로 변환
- 클릭 기반 흐름을 **음성 중심 단일 인터랙션**으로 전환

---

## 음성 기반 주문 처리 흐름

음성 입력  
→ Whisper(STT)  
→ 자연어 텍스트  
→ Qwen(LLM) 분석  
→ 주문 의도 / 날짜 / 품목 JSON 구조화  
→ 주문 세션 상태 업데이트 및 응답 생성

---

## AI 적용 상세

### 1. 음성 인식 (ASR)

- Whisper 기반 음성 인식 모델 사용
- 사용자의 자유 발화를 텍스트로 변환
- 프론트엔드에서 전달되는 `webm` 음성 파일 처리

### 2. 주문 도메인 파인튜닝 (LLM)

- 주문 도메인(메뉴, 수량, 단위, 추가·수정·삭제)에 특화된  
  **학습용 발화 데이터셋을 직접 구축**
- 자연어 주문을 아래와 같은 JSON 스키마로 안정적으로 변환하도록  
  LLM 파인튜닝(LoRA 방식) 적용

예시 출력 형식:
- intent
- date
- items(name, qty, unit)

- 학습 과정에서
  - epoch, learning rate 등 하이퍼파라미터를 조절하며 실험
  - JSON 파싱 성공률과 출력 형식 준수 여부를 기준으로 성능 평가
- 그 결과
  - 후처리 로직 의존도를 줄이고
  - 주문 세션 로직과의 결합도를 낮춤

---

## 주문 세션 관리 로직

- AI 분석 결과(`intent`, `items`)를 기반으로 주문 상태를 단계적으로 관리
- 다음과 같은 발화를 처리
  - 디너 메뉴 선택
  - 서빙 스타일 선택
  - 메뉴 추가 / 수량 변경 / 삭제
  - 주문 확인 및 종료
- 이전 발화를 기억하여 **대화형 주문 흐름 유지**

## 기술 스택

- Frontend
  - React  
  - Web Audio API 기반 음성 녹음 및 전송

- Backend
  - Spring Boot (Java)

- AI / ML
  - Whisper (Speech-to-Text)
  - Qwen (자연어 주문 분석, 파인튜닝 적용)

- Communication
  - REST API
  - ngrok 기반 로컬 AI 서버 외부 연동

- Data Format
  - JSON 기반 주문 구조
